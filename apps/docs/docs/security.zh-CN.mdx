MDX 中可以包含可执行 JavaScript。`@amamo/mdx` 会编译它,但不沙箱化它。Schema 校验不是
沙箱。本包按构造给出一小撮保证,这一页把它们列出来。

## 可信作者

只编译你信任的作者写的内容。编译器会乐呵呵地跑包含
`import { exec } from 'node:child_process'` 的 MDX、调 `fetch` 访问内网,或者在 `{...}`
里求值任意表达式。这里没有"安全 MDX"白名单,也没有运行时的污点追踪。

## 敏感字段

把任何不应进入打包产物的字段在所属集合里标为 `sensitive`:

```ts
collections: {
  posts: {
    directory: 'content/posts',
    schema: { /* ... */ },
    sensitive: ['password', 'internalNotes'],
  },
}
```

敏感字段在编译器写盘之前就被移除。缓存记录、生成模块、私有加载器索引,以及所有公开 manifest
从一开始就没见过这个字段。没有任何开关能让明文再次出现。

## manifest 投影

manifest 字段投影读敏感源只能是 `'exists'` 或 `'sha256'`:

```ts
manifests: {
  server: {
    output: '.amamo-mdx/server.json',
    fields: {
      key: 'key',
      protected: { from: 'password', transform: 'exists' },
      passwordHash: { from: 'password', transform: 'sha256' },
    },
  },
}
```

`'exists'` 根据源字段是否存在输出 `true` 或 `false`。`'sha256'` 输出源字段的十六进制
SHA-256。除此之外的形式 —— 包括直接复制字符串 —— 会被拒绝。编译器是唯一见过明文的部分,
它在校验完成后就把字段丢弃。

服务端密码校验就是按这个套路工作:宿主应用拿到哈希,对自己拿到的用户输入做一次哈希,比较
两者的结果。明文从未离开编译器。

## 路径包含

相对媒体 URL 相对于所在的 MDX 文件解析,然后与配置的 `root` 校验。解析后落到 root 之外的
URL —— 即使是经过符号链接 —— 会被拒绝。编译器既不允许相对路径穿过 root,也不允许以 `/`
或 `..` 起头逃出包含。

## 缓存写入

编译记录与高亮器缓存都按"同目录临时文件 + 原子 rename"的模式写入。读端在写期间打开
缓存,要么看到旧文件,要么看到新文件,绝不会看到半成品。缓存目录本身位于
`generatedDirectory` 下,宿主应用可以把 `generatedDirectory` 放在 tmpfs 或排除出备份,其它
什么都不用动。

## 纯数据配置

配置被限制为纯可序列化数据。函数、类实例、symbol 键、循环引用都会在构造时被拒绝。指纹是
在归一化后的纯数据形态上算的,因此两份产出同样归一化形式的配置会产生同样的缓存记录 ——
即使其中一份重新排了对象的键。

## 诊断

当构建因安全相关原因失败时,诊断信息会具体指向问题:它会标明字段、集合和路径。诊断永远
不会包含敏感字段的值。
